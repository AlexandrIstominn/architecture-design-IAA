# Отчет по лабораторной работе №5

Тема: Реализация микросервисной архитектуры на основе контейнеров Docker

## 1. Архитектура системы

Согласно диаграмме контейнеров, приложение было разделено на 3 независимых сервиса:

- `api`: реализован на ASP.NET Core (.NET 8). Содержит бизнес-логику анализа аккаунтов, работу с очередью задач и CRUD API.
- `db`: PostgreSQL. Используется для хранения пользователей, аккаунтов, истории анализов, результатов и отчетов.
- `frontend`: клиент на Node.js (Express + статические файлы). Отображает интерфейс пользователя и отправляет запросы в API.

## 2. Интеграционные тесты

Интеграционные тесты реализованы двумя способами:

- контейнерные API-тесты через Postman/Newman (`tests/postman`)
- интеграционные тесты на xUnit (`tests/BotDetect.Api.Tests`)

Сценарий тестирования:

- ожидание готовности PostgreSQL и API в CI-пайплайне;
- проверка основных endpoint API (`/api/analysis`, `/api/accounts`, `/api/reports`);
- валидация статусов ответа и структуры JSON.


## 3. CI

Настроен GitHub Actions workflow `ci.yml`. При каждом push/pull request в `main`/`master`/`develop` автоматически выполняются:

- сборка решения (`dotnet restore`, `dotnet build`);
- запуск интеграционных тестов xUnit;
- сборка Docker-образов API и frontend;
- запуск Postman-коллекции через Newman и публикация отчета как artifact.

## 4. Непрерывное развертывание (CD)

Настроен GitHub Actions workflow `cd.yml`. При push в `main`/`master` и при публикации Release выполняется:

- сборка Docker-образов `botdetect-api` и `botdetect-frontend`;
- публикация образов в Docker Hub.

## 5. Результаты работы

В ходе работы реализована микросервисная архитектура, настроено взаимодействие контейнеров через внутреннюю сеть Docker, автоматизировано интеграционное тестирование и настроено непрерывное развертывание с публикацией Docker-образов в Docker Hub.
